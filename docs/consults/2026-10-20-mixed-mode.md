### Seat: `openai/gpt-6-astra`
*Verdict: Approve guest-memory RoutineDescriptors plus a non-recursive callback continuation machine; reject TVector-as-universal-UPP and trap replay after callback side effects. The supplied RAG contains no Inside Macintosh Mixed Mode material and no relevant Linux/Haiku/FreeBSD/Mesa/i915 implementation. Its tests support validation principles only, not Macintosh ABI claims. This is a design ruling, not a claim that the three applications are already covered.*
- **1. Real RoutineDescriptors; one parser and explicit callable kinds**: NewRoutineDescriptor returns a guest pointer to a real, big-endian, 2-byte-packed RoutineDescriptor, not the procedure's TVector. The historical layout to verify and pin is: header offsets 0:u16 goMixedModeTrap=0xAAFE, 2:i8 version=7, 3:u8 descriptorFlags, 4:u32 reserved1, 8:u8 reserved2, 9:u8 selectorInfo, 10:u16 routineCount; records begin at 12. Each 20-byte RoutineRecord contains +0:u32 procInfo, +4:i8 reserved1, +5:u8 ISA, +6:u16 routineFlags, +8:u32 procDescriptor, +12:u32 reserved2, +16:u32 selector. routineCount is the last record index: zero means one record. NewRoutineDescriptor(userRoutine, procInfo, ISA) constructs one record; for a PPC record procDescriptor identifies a TVector, whereas a 68k record identifies 68k code. NewFatRoutineDescriptor(m68kProc, powerPCProc, procInfo) constructs two records and sets routineCount=1; construction need not imply both ISAs can execute. Decode flags and selectors using the historical rules, never a first-record-always shortcut. Unsupported selection forms produce a named refusal before invoking code.

Use private-field GuestAddr, RoutineDescriptorAddr and TVectorAddr types, plus ResolvedCallable::{PpcTVector, M68kCode, HostTrap}. mixed_mode owns the sole RD parser, checked size arithmetic and procInfo decoder. Accept valid guest-authored/static descriptors as well as allocator-created descriptors; an allocation ledger is ownership information, not a whitelist of callable descriptors. Validate the complete selected record and target before changing CPU state. Never interpret guest addresses as host pointers.

DisposeRoutineDescriptor disposes a dynamically allocated descriptor, not its target procedure or TVector. Track allocation provenance and prevent host double-free or stale host references; apply the documented null behavior after verifying the primary source. A currently scheduled call holds an owned, validated call description, not a Rust borrow into descriptor memory. Guest-authored/static descriptors are not allocator-owned objects to free.

CallUniversalProc(upp, procInfo, ...) decodes the caller's argument representation, resolves the UPP and schedules a call. Universal pointers can designate real RDs or legacy raw 68k procedures; arbitrary non-RD memory must not be guessed to be a PPC TVector. A native callback contract such as StdCLib qsort explicitly supplies a PPC function pointer/TVector and uses that separate resolver. Native-only UPP macros or typedef optimizations do not justify implementing the Mixed Mode constructor as an identity function. NewRoutineDescriptorTrap must converge on the same semantic constructor, but its trap/import entry ABI must be verified separately rather than assumed identical from its name.
  - *Rationale*: Applications can inspect or statically construct descriptors, and Mixed Mode needs ISA, signature and selection information that a TVector alone cannot encode. One total parser prevents the two engines from accepting different malformed descriptors. Citation 3 illustrates why representation identity and object identity must remain distinct; citation 2 supplies a useful exhaustive-bit-test pattern, but its masking policy must not be copied blindly into a historical format that may require rejection.
- **2. Callback scheduling and typed handler resumption**: Introduce ToolboxStep::{Complete(ToolboxResult), Invoke(CallbackRequest, Continuation), Wait(WaitKey, Continuation), Refused(MixedModeError)}. CallbackRequest owns the resolved target, validated CallSignature and argument values. Continuation is a concrete enum, initially UserItems{dialog, next_item, remaining_state}, ModalDialog{dialog, phase, event, item_hit_addr}, WindowDefinition{window, message, phase}, and UniversalProcReturn{result_contract}. Add variants only with an executing caller. The shared Toolbox emits these steps; each CPU adapter implements entry/return mechanics. No handler calls either interpreter.

Maintain a per-emulated-Mac Vec<CallbackFrame>, not a library static or a singleton pending Option. CallbackFrame contains the suspended glue-call identity, saved PPC architectural context, original caller LR, continuation, result contract and expected callback-return state. Save enough state to resume the interrupted glue operation exactly; initially a complete CPU snapshot is simpler than an incomplete register subset. Validate and allocate before committing the frame and CPU changes.

For PPC entry: read the TVector's code and TOC; create a guest stack call frame with the Classic Mac PPC ABI's verified alignment, linkage area and parameter-save area; set r1 to that frame, r2=TOC, r12=TVector, PC=code and LR=the engine's callback-return glue address. Marshal supported scalar/pointer arguments into r3..r10; later arguments and compound types require their actual ABI rules, not consecutive-register guessing. Preserve the caller's TOC for restoration. The first slice may refuse signatures requiring unsupported stack, floating-point, aggregate or special register marshalling before entering the callback.

The interpreter's outer loop executes the callback normally. At the callback-return glue, require a matching live frame, capture r3 according to the result contract, restore the suspended CPU context and feed the result into its Continuation. Guest-memory writes remain visible. The continuation returns Complete, schedules the next callback, waits, or refuses. Complete finally returns to the original glue caller; callback-return itself must not perform an ordinary blr to its own LR.

A user-item run advances its cursor exactly once after each return. ModalDialog retains its event and phase across the filter callback; a false filter result proceeds to default handling without fetching a second event. Waiting blocks the hosting task on an event/wakeup. Retrying the glue address is allowed only as an entry into stored continuation state, never by replaying the original trap body. Nested callbacks and nested Toolbox calls push frames and unwind LIFO.
  - *Rationale*: This extends the existing 68k deferred-call model without retaining a Rust stack or borrowing Mac across guest execution. Explicit phases make side effects exactly-once. Citation 7 demonstrates a real callback consequence: application activity can change objects that the caller must revalidate before continuing. Citation 4 supports signature-checking at callback boundaries, but is not evidence for PPC register conventions.

Citation 1's negative tests embody the applicable invariant: a named target must resolve to that target or fail, never fall through to a different execution domain.
- **4. Trap-address identity is a real guest ABI**: Use the shared trap registry as the sole authority for NGetTrapAddress, GetToolTrapAddress and GetOSTrapAddress. Normalize trap number and table selection according to each documented entry point; do not derive availability from the InterfaceLib import list. Unimplemented slots return the same canonical guest 68k _Unimplemented entry address. Implemented slots return their stable guest 68k entry addresses. WaitNextEvent therefore differs from _Unimplemented only when its shared trap implementation is present. The explicit Toolbox/OS forms must select the correct table even where numeric indices overlap.

Return guest 68k procedure addresses, not Rust pointers, PPC glue PCs or TVectors. Query the current trap table so SetTrapAddress patches are observable, while previously returned original bridge addresses remain valid for chaining. A PPC application may save and compare these addresses, and may request their invocation through Mixed Mode; address-query success does not mean the pointer is directly executable with PPC branch instructions.

CallUniversalProc resolving an exact registered synthetic 68k bridge can dispatch its existing Rust Toolbox handler through the same continuation machinery, provided that signature is supported. Recognize bridges by registry identity, not by accepting any address in a broad low-memory range. Arbitrary patched 68k code remains subject to section 3's named refusal. If a trap has been patched, fetching its address returns the patch, not the original bridge.
  - *Rationale*: This makes TrapAvailable-style comparisons truthful without fabricating a second trap universe. Citation 3 directly motivates returning the identified object rather than an unrelated slot or surrogate. Bridge invocation reuses the actual shared Toolbox instead of implementing a parallel approximate handler.
