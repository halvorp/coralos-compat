# mac68k-engine skeleton (2026-10-18)

Goal: prove the shared crates serve a SECOND engine without copying code. A hand-assembled classic Mac 68k program
runs through the same `retro-m68k` core and the same `guestui-abi` trait as the Amiga engine, with Toolbox calls
(A-line traps) bridged onto `GuestUi`.

## What runs

`crates/mac68k-engine/fixtures/hello.s` (assembled with `m68k-linux-gnu-as -m68020`, bytes in `hello.bin`):
InitGraf, InitFonts, InitWindows, InitMenus, TEInit, InitDialogs, InitCursor, `NewWindow("Hello Mac", Rect 40,30,240,350)`,
`DisposeWindow`, `ExitToShell`. On `RecordingGuestUi` that is `OpenWindow{title "Hello Mac", left 30 top 40 w 320 h 200}`
then `CloseWindow`. Tests: `crates/mac68k-engine/tests/toolbox_end_to_end.rs` (each behaviour has a negative control).

Flow: `Mac::start(code, entry)` places a flat image at `CODE_BASE` (0x10000) -> `step(budget)` -> an A-line word reaches
`retro_m68k::Host::aline` -> `traps::trap_key` -> table lookup -> `pascal::read_args` (the Pascal convention, once) ->
named handler in `toolbox.rs` -> `pascal::complete` (pop args, store the result). `deliver(event)` and `run_program`
mirror the Amiga names. `Mac::stop_on_unimplemented` is census mode.

## Refusals

A trap the table does not implement is the refusal `unimplemented trap _NewWindow ($A913)` (`$A81E (unnamed)` if no
table names the word). Census mode halts at it; otherwise D0 = 0 and execution continues with the stack untouched
(an unknown trap has no known signature, so its arguments stay on the stack). A bad guest pointer in an implemented trap
is a named refusal too; the arguments are still popped, the result is 0.

Trap names: `src/trap_names.rs` is GENERATED by `tools/gen-trap-names.py` from metamage_1's `relix/files/etc/traps`
(839 trap words; interface facts only, no code copied). The six well-known numbers are asserted by the generator and
by `traps::tests`.

## Shared crates: reused unchanged / extended / new

- Unchanged: `guestui-abi` (WindowModel, GuestUi, RecordingGuestUi, events), `retro-guest-mem`'s `GuestMem`.
- Extended `retro-m68k`: `Host::aline(cpu, opcode, pc) -> bool` (default declines) and `retro_aline_hook`, called from
  Musashi's `m68ki_exception_1010` (vendor/m68kcpu.h, one `if`; prototype in m68kconf.h). Handled = PC is already past the
  word and NO exception frame is built, so the trap's stack arguments are still on top. Declined = the normal line-1010
  exception. The Amiga engine does not override it. Two tests, one a negative control.
- MOVED out of amiga68k-engine into shared code (Amiga re-exports them, behaviour unchanged):
  `Heap` (first-fit guest allocator) -> `retro-guest-mem::heap` (its Amiga-only `forbid` counter became a field of
  `Amiga`); `Refusal` and `Step` -> new `retro-common`.
- Mac-only: trap table, Pascal frame helper, Toolbox handlers.

## Stubbed / not true yet

- No resource fork, no `CODE` resources, no A5 world: the image is a flat blob (entry = offset into it).
- Init* calls are accepted and logged only. Only Toolbox traps (Pascal convention) are registered; the OS-trap half ($A000-$A7FF,
  register convention, D0 = OSErr) has a key space and names but no handler kind yet.
- NewWindow: `visible=false` is not honoured (the native window is always opened), `behind` is ignored, no GrafPort
  contents beyond zeroing the WindowRecord and setting visible / goAwayFlag / refCon. `theProc` maps to role/resizable only.
- Str255 bytes above 0x7F are shown as Latin-1, not MacRoman.
- `deliver(CloseRequested)` queues `(mouseDown, WindowPtr)` in `Mac::pending`; nothing consumes it until GetNextEvent.
- Structure layouts (Rect, WindowRecord size 156 and field offsets) are from Inside Macintosh and must be re-verified.

## Next steps

1. Resource fork reader (AppleSingle/AppleDouble/MacBinary) and a `CODE` resource loader: CODE 0 jump table, A5 world,
   segment loading via `_LoadSeg`/`_UnloadSeg` traps, QuickDraw globals at A5.
2. QuickDraw onto guestui: GrafPort/`SetPort`, `MoveTo`/`LineTo`/`FrameRect`/`PaintRect`/`DrawString`, drawn into the
   window's surface via the (still to be defined) guestui drawing model.
3. The event loop: `GetNextEvent` / `WaitNextEvent` ($A970/$A860) map onto the resumable step model exactly as the
   Amiga `Wait`/`WaitPort` do: with no event pending (and sleep > 0) the trap `Cpu::block`s; `deliver` queues an
   EventRecord; the next `step` resumes with the result. Then FindWindow/TrackGoAway/CloseWindow, menus
   (`GetMenuBar`/`MenuSelect`) onto `set_menu_strip`.
4. OS traps with register conventions (Memory Manager `NewPtr`/`NewHandle` on the shared Heap, `GetResource`), and
   registering a handler kind for them next to the Pascal one.
